# Control de la Slide solo con el mando: sistema "Ajustes" de EmulationStation (2026-11-26)

## 1. Como lo resuelven otros handhelds (investigado)
- **ROCKNIX/JELOS**: menu propio dentro de su fork de ES (Start > Network Settings / Controller & Bluetooth), teclado en pantalla de ES; "Tools" es un sistema de ES que lanza scripts. https://rocknix.org/configure/networking , https://rocknix.org/configure/bluetooth , https://deepwiki.com/ROCKNIX/distribution/4.2-input-configuration (gptokeyb para apps que solo leen teclado).
- **Batocera**: igual, menus nativos de su ES (Network Settings, Pair a Bluetooth device) sobre scripts `batocera-wifi`, `batocera-bluetooth`, `batocera-audio`. https://wiki.batocera.org/menu_tree , https://wiki.batocera.org/wifi_ssid
- **muOS**: frontend propio (`muxnetwork`, `muxconnect`, Bluetooth) en SDL, no ES. https://muos.dev/tour/modules/muxconnect ; app Bluetooth aparte https://github.com/hardwarebob/bltMuos
- **ArkOS/dArkOS**: ES clasico + sistema "Options"/"Tools" con scripts `.sh` (Wifi.sh, Bluetooth Manager) que usan `dialog` + `gptokeyb` (gamepad->teclado). https://retrogamecorps.com/2023/03/27/arkos-starter-guide , https://github.com/djparentx/Wi-Fi-Manager , https://github.com/christianhaitian/dArkOS
- **RetroPie**: sistema "retropie" (`retropiemenu`) cuyos "juegos" son `.sh`; `runcommand` y los menus `dialog` se manejan con `joy2key` (gamepad->teclas por tty). https://retropie.org.uk/docs/Runcommand/ , https://retropie.org.uk/docs/Wifi , https://github.com/RetroPie/RetroPie-Setup/blob/master/scriptmodules/supplementary/retropiemenu.sh
- Patron comun: **un sistema de ES cuyos "juegos" son scripts**, con una UI de consola (dialog) movida por joy2key/gptokeyb. (Los menus nativos de ROCKNIX/Batocera necesitan modificar ES: no es nuestro caso.)

## 2. Que encaja aqui y por que (elegido)
`dialog`/`whiptail`+joy2key no sirven: la Slide **no tiene consola en pantalla** (la pantalla solo existe via hybris/EGL `drm`, no hay fbcon ni X), y `dialog` no esta instalado. Opcion elegida: **ES sistema `settings` + mini-GUI propia `rgslide-ui`** (C, SDL2 driver hybris + GLES2, fuente DejaVu Sans Mono con stb_truetype, mismo patron que `tools/sdltest`). Ventajas: se ve con la Mali como ES, lee el mando directamente (sin uinput/gptokeyb), lleva teclado en pantalla para las claves wifi y sliders/selectores. ES libera la pantalla antes de lanzar el comando (`FileData::launchGame` hace `window->deinit()`), por lo que `rgslide-ui` la usa y al salir ES la recupera. Es el mismo mecanismo que ya usa RetroArch desde ES, probado.

## 3. Piezas (todas nuevas, en el overlay)
- `rootfs/overlay/usr/local/bin/rgslide-ctl` (sh POSIX): `status [all|wifi|bt|screen|time|power]`, `wifi list|saved|status|connect SSID [CLAVE]|forget SSID`, `bt get|status|power|scan|devices|pair|connect|disconnect|remove`, `brightness`, `volume`, `fan`, `display`, `net`, `time get|sync|adjust +-MIN|tz`, `reboot`, `poweroff`; `--dry-run` delante evita efectos (reboot/poweroff/time/fan/brillo/wifi). Llama a `rgslide-brightness`, `rgslide-fan`, `rgslide-volume` si existen; si no, "no disponible".
- `tools/rgslide-ui/rgslide-ui.c` (+ `stb_truetype.h`, dominio publico): binario `/usr/local/bin/rgslide-ui`. Compilacion (cruzada, clang del NDK, ver orden en esta nota): `clang --target=aarch64-linux-gnu --sysroot=out/sysroot-trixie -fuse-ld=lld -O2 -I$SD/include/SDL2 -I<GLES2 headers del NDK> -o out/rgslide-ui tools/rgslide-ui/rgslide-ui.c -L<stub libGLESv2.so.2> -L$SD/lib -lGLESv2 -lSDL2 -lm -Wl,--allow-shlib-undefined` (`SD=out/sdl2-hybris-root/usr/local/sdl2-hybris`; el stub es una .so vacia con los simbolos gl*, solo para enlazar). NO esta en el overlay (binario).
- Menus declarativos `rootfs/overlay/usr/share/rgslide/ui/{panel,wifi,bluetooth,screen,time,power}.menu` (lineas `run|etiqueta|cmd`, `confirm|..`, `slider|etq|min|max|paso|get|set %d`, `choice|etq|get|set %s|op1,op2`, `list|etq|cmd lista|cmd accion %s %p`; `%s`=valor elegido, `%p`=texto del teclado; la lista imprime `valor<TAB>texto<TAB>pregunta-de-clave`). `rgslide-ui --view TITULO CMD [SEG]` muestra la salida de un comando (con refresco cada SEG s).
- Sistema ES `settings` (UNO nuevo al final de `es_systems.cfg`, `<command>/bin/sh %ROM%</command>`, ruta `/home/console/roms/settings`) con los "juegos" `rootfs/overlay/usr/share/rgslide/settings/*.sh` (00 Panel de control, 01 Estado, 02 Wifi, 03 Bluetooth, 04 Pantalla y sonido, 05 Hora y fecha, 06 Reiniciar o apagar), copiados a `~/roms/settings/`. Tema: `etc/emulationstation/themes/carbon/settings/theme.xml` (sin el, ES avisaba de logos que faltan; ahora solo el aviso inofensivo `could not find file ""` del carbon.xml como el resto).
- Mando en `rgslide-ui`: hat/stick = mover (con repeticion), A = aceptar, B = volver (en el teclado = borrar), X = refrescar/espacio, Y = capa del teclado, L/R = pagina, Select+Start = salir. Izq/Der cambia sliders y selectores en el momento (se aplica al instante).

## 5. Frecuencia de pantalla
- Fichero `/etc/default/rgslide-display` (copia en `rootfs/overlay/etc/default/rgslide-display`), `REFRESH=60|120|auto`, defecto 60. Base: `docs/agent-refresh.md` (modos 60/90/120; 90 inestable, no se ofrece; 120 Hz = ~108 fps en hybristest, +14 % de corriente).
- `rgslide-ctl display get|set 60|120|auto`: valida el valor (otro -> error y no escribe), escribe con `sudo tee` y avisa "se aplica al REINICIAR ES (no en caliente)". Probado por ssh: set 120, auto, 60 y 99 (rechazado) -> `get` devuelve lo esperado; `--dry-run display set 120` no escribe. Valor final dejado en **60**.
- `rgslide-es` lee el fichero en cada vuelta del bucle (antes de lanzar ES) y `rgslide-es-launch` en cada juego: `60` -> no exportan nada (se hace `unset HYBRIS_DRM_REFRESH`); `120` -> `HYBRIS_DRM_REFRESH=120` para ES y RetroArch; **`auto` = ES a 120 Hz y RetroArch a 60 Hz (sin variable)**; los juegos retro son 60 Hz y 120 Hz en RetroArch NO esta probado. Comprobado solo la logica (tabla 60 -> -/-, 120 -> 120/120, auto -> 120/-), no un arranque a 120.
- Menu: entrada `Pantalla (al reiniciar ES)` con `< 60 / 120 / auto >` y valor actual en `panel.menu` y `screen.menu`; el resumen de estado muestra `Pantalla: N Hz`. "Se aplica al reiniciar ES": salir de ES por Start > Quit > Restart ES (o `systemctl restart rgslide-es`).
- NO hecho: el `.so` de libhybris con `HYBRIS_DRM_REFRESH` (patch 0004) NO esta instalado en /opt/hybris*; hasta que el coordinador lo instale, 120/auto no cambian nada visible (la variable se ignora). No se toco la pantalla ni se reinicio ES para esto.
